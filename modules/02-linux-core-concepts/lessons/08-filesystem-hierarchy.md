# The Filesystem Hierarchy

## Why this matters

Marco's horror story about someone deleting half of `/var` happened because
the person didn't know what lives there. Linux distributions follow the
**Filesystem Hierarchy Standard (FHS)**, so once you learn the layout, you
know where things are on almost any Linux machine.

## Concepts

Everything hangs off one root, `/`. Additional disks are attached
(**mounted**) somewhere inside that tree rather than getting drive letters.

| Directory | Contains | Bob should know |
|---|---|---|
| `/bin`, `/sbin` | essential commands (`ls`, `cp`) and admin commands (`fdisk`, `ip`) | on modern distributions these are symlinks into `/usr` |
| `/usr` | the bulk of installed software: `/usr/bin`, `/usr/lib`, `/usr/share` (docs, man pages) | managed by the package manager — don't hand-edit |
| `/usr/local` | software you install yourself, outside the package manager | safe from package updates |
| `/opt` | add-on application bundles (`/opt/tools`, vendor software) | one subdirectory per application |
| `/etc` | system-wide **configuration** files, all text | back it up; edit carefully |
| `/home` | users' home directories (`/home/bob`) | user data |
| `/root` | the root user's home directory | not the same as `/` |
| `/var` | **variable** data: logs (`/var/log`), caches, mail, databases (`/var/lib`) | grows over time; a full `/var` breaks services |
| `/tmp` | temporary files for everyone, often cleared at boot | never keep anything important here |
| `/boot` | kernel, initramfs, GRUB files | a full `/boot` breaks kernel updates |
| `/dev` | device files created by udev | |
| `/proc`, `/sys` | virtual filesystems generated by the kernel | nothing here is on disk |
| `/run` | runtime data since boot: PID files, sockets | in RAM, cleared on reboot |
| `/mnt`, `/media` | mount points: `/mnt` for temporary manual mounts, `/media` for removable media | |
| `/srv` | data served by this machine (web roots, FTP, NFS exports) | |
| `/lib`, `/lib64` | shared libraries and kernel modules (`/lib/modules`) | symlinks into `/usr` on modern systems |

### Where are the logs?

Most logs live in `/var/log`, but the main system log differs by family:

- Debian/Ubuntu: `/var/log/syslog` (when rsyslog is installed)
- Red Hat/Rocky: `/var/log/messages`
- Everywhere with systemd: the journal, read with `journalctl`

## Try it

The top of the tree:

```bash
ls /
```

```text
bin		   dev	 lib.usr-is-merged  opt   sbin		      tmp
bin.usr-is-merged  etc	 lib64		    proc  sbin.usr-is-merged  usr
boot		   home  media		    root  srv		      var
course		   lib	 mnt		    run   sys
```

(`course` exists only in the lab containers: it's the course repository,
mounted read-only.)

Modern distributions merged `/bin` into `/usr/bin`:

```bash
ls -ld /bin /sbin /lib
```

```text
lrwxrwxrwx 1 root root 7 Apr 22  2024 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 Apr 22  2024 /lib -> usr/lib
lrwxrwxrwx 1 root root 8 Apr 22  2024 /sbin -> usr/sbin
```

Configuration is plain text in `/etc`, variable data in `/var`:

```bash
head -3 /etc/os-release
ls /var
ls /var/log | head -5
```

```text
PRETTY_NAME="Ubuntu 24.04.5 LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
backups  cache	lib  local  lock  log  mail  opt  run  spool  tmp
README
alternatives.log
apt
bootstrap.log
btmp
```

How much space does each top-level directory under `/usr` use?

```bash
du -sh /usr/* 2>/dev/null | sort -h | tail -4
```

```text
9.6M	/usr/sbin
43M	/usr/bin
83M	/usr/share
159M	/usr/lib
```

## Common mistakes

- **Storing data in `/tmp`.** It may vanish on reboot.
- **Editing files under `/usr` installed by packages.** Updates overwrite
  them. Put local changes in `/etc` or `/usr/local`.
- **Confusing `/root` with `/`.** `/root` is just root's home directory.
- **Deleting "big log files" in `/var` without checking.** `/var/lib` holds
  databases and package state, not logs.

## Recap

- One tree from `/`; extra storage is mounted into it.
- Config in `/etc`, programs in `/usr` (and `/opt`, `/usr/local`), variable
  data and logs in `/var`, users in `/home`.
- `/proc`, `/sys`, `/run` and `/dev` are created at runtime, not stored on
  disk.
